# 页面流向（Sankey）口径与审查记录

## 统计口径

接口：`GET /api/stats/:domain/user-flows`，沿用现有统计路由的JWT、API Key和共享链接站点校验。

- 时间按站点时区解析，支持标准统计周期及自定义起止日期。
- 一条路径以 `(user_id, session_id)` 区分，且只包含所选时间范围内的 `pageview`；缺失session_id的事件不参与，业务事件和热力点击不算页面跳转。
- 第一步是范围内首次观察到的页面，不保证是跨日期会话的真实落地页。`entry_path`限定这一步，不会从会话中途任意页面重新起算。
- 连续相同pathname合并后取前2–4步；非连续的重复页面保留，例如 `/a → /b → /a`。
- 全局筛选先选出包含匹配事件的会话，再保留这些会话在范围内的完整浏览路径。例如筛选`event:page=/pricing`时，仍可看到该会话经过的首页和其他中间页；多个条件沿用统计筛选器的布尔及跨表语义。
- 每一步按全部匹配会话的页面到达量取Top N，长尾页面汇入“其他页面”。同量按页面名称排序，结果稳定；“其他”和“未观察到后续页面”均有独立类型，不与真实页面字符串混用。
- `total_sessions`是图中起始会话数；`drop_off_sessions`是未达到所选最后一步的会话数；`drop_off_rate`为两者之比。达到最后一步即停止展示，不再追加强制退出边。

“未观察到后续页面”可能来自真实离站、仍在浏览、时间范围截断或采集缺失，不能据此断言浏览器关闭、用户流失或真实退出率。到达末步也不代表业务留存。表格中的连线占比以全部起始会话为分母，不同深度的占比不能相加。

现有events.timestamp精度为秒，无法恢复同一秒内多个页面的真实先后；同秒按pathname稳定排序。当前按pathname聚合，同站点不同hostname的同路径会合并。若需要精确的跨子域旅程或同秒动作顺序，应另行增加主机维度及采集顺序字段，本次不改变采集协议和历史表结构。

## 2026-11-10审查发现及修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 每条路径末尾强制添加Exit，包括达到展示步数的路径 | 流失率恒为100%，深度会话恒为0 | 只在最后展示步之前缺少后续页时计数 |
| 只返回热门1000种完整路径 | 总会话、长尾和比例不完整 | 全部会话参与Top N和连线聚合，返回规模由图的节点数限定 |
| 截断原始pageviews后再连续去重 | 重复刷新吃掉步数，误判无后续路径 | 先按窗口识别相邻重复，再有界保留前N个跳转 |
| 依赖子查询ORDER BY后groupArray的隐含顺序 | 并行聚合下顺序不可靠 | 明确窗口排序及groupArraySorted，确定同秒排序规则 |
| 忽略filters，使用不完整的周期解析 | 筛选图表不一致，非法周期可能触发异常扫描 | 复用统计校验、时区和筛选SQL构建器 |
| 通用日期解析器复用Carbon可变对象 | 部分周期起止时间塌缩，接口成功却返回空图 | 为起始边界复制日期对象；自定义纯日期包含最后一整天，补充DST测试 |
| 跨表筛选仅按session_id关联 | 不同用户同ID时串入其他路径 | 改用user_id与session_id组合关联 |
| 查询绕过既有统计并发预算，传入Gin context | 额外内存竞争，关闭页面不能可靠取消查询 | 共享统计查询槽位，使用Request.Context并传递取消 |
| 请求返回顺序无保护，错误显示为空数据 | 旧请求覆盖新筛选，数据库故障被误读为无流量 | AbortController及过期响应检查；独立错误与重试状态 |
| 各列单独缩放，移动端SVG与布局宽度不一致 | 同样会话数的连线粗细不同、重叠或溢出 | 所有连线使用统一比例；标签空间独立，窄屏可横向滚动 |
| 渲染时原地排序data.links、未区分Other节点 | 修改React状态、错误提供聚合节点筛选 | 复制后排序，聚合节点不可作为起始页 |

## 资源保护与验证

流向与常规统计共享每个API进程最多2个查询的预算。单次流向查询线程数1、执行上限20秒、含排队总超时25秒、内存上限256 MiB，聚合和排序超过64 MiB可落盘。ClickHouse资源限制和context超时遵循统计接口的可重试`code:503`约定。多实例不是全局共享预算，漏斗等独立查询路径仍有各自预算。

每个会话只保留最多4个页面跳转；返回最多 `(steps-1)*(limit+1)*(limit+2)` 条边，无完整路径数量的静默截断。路径扫描与排序仍随事件量增长，这不等于大流量下30天查询恒定耗时；更大规模可在明确跨日会话语义后增设路径摘要或离线分析。

真实ClickHouse隔离测试覆盖1万次连续重复页、超过1000种路径、2/3/4步、入口和国家/事件/页面/真实Session入口筛选、不同用户相同Session ID、时间边界、Top N稳定性与图的流量守恒。浏览器测试覆盖移动端几何比例、全局筛选传递、故障重试及请求竞态。

本地已有演示数据的30天接口验收：1580个会话，3步时43个会话到达末步（未达到末步比例97.28%）；2步时87个到达末步。筛选包含`/pricing`的会话得到98个会话，仍保留其完整路径。以上为本地演示数据，不代表生产流量。

本次不修改生产配置或部署，不重写历史事件、Session、PV与UV。
